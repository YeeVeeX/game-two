## Stage 1 — GRILL (declare the budget first; grill ≥ implementation)

Two findings from the hub seat are your starting material. **Re-verify both, then attack
them.**

- **Stall semantics:** `lockstep.rb:92` `ready?` gates on the PEER's queue (local present
  by construction); `session.rb` calls `record_stall` only in the `else` of `run_tick`.
  ⇒ `stalls=N` = "this seat waited N updates for the other seat". Host 9807 vs joiner 136
  therefore says the **low-stall seat is the limiter** — suspicion moves off host CPU.
- **Delay arithmetic:** `data/netplay.json` → `delay {min 4, max 12, default 8,
  jitter_margin_ticks 3}`, `probe_count 5`. At 60 tps, D=8 ≈ **133 ms** of cover against a
  measured **165 ms RTT** (~82 ms one-way + jitter). **The negotiated D and the RTT probe
  samples are logged NOWHERE** — the cheapest diagnostic in this lane does not exist yet.

Grill questions to answer in writing (debate, do not transcribe):
1. What is the smallest set of numbers that DECIDES between: (a) peer seat too slow,
   (b) D under-covering the path, (c) path flap direct↔DERP, (d) focus throttle on a
   spectating/dead seat, (e) host duties? Kill every metric that does not discriminate.
2. Which hypotheses can a **zero-code probe** settle? (Role swap, audio off, focus held,
   `tailscale status` sampled during play.) Anything a probe settles must NOT be built.
3. Can the stall counter alone lie? (e.g. both seats stalling on the same tick; a seat
   that never stalls because it is behind.) Name the failure mode and how the new numbers
   avoid it.
4. What is the risk of the instrumentation itself changing the thing measured (clock reads
   per update, allocation, log volume at 60 Hz)?
5. Non-goals for this item, stated: no netcode redesign, no rollback, no UDP, no pacing
   value changes, no visible surface.

**Output:** a spec block appended to `drafts/_netplay-lag-forensics-20260819.md` (or a
sibling spec file) with: the corrected stall reading + citations, the D arithmetic, the
decisive metric set, the probe matrix, non-goals, and the verification strategy. Struck
claims stay struck-through in place, never deleted.
