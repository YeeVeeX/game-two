## The bug (reproduced live before fixing — the reviewer's trace was static)

`Creature#begin_action` read `cfg = kit.fetch(kind)` (skill N of the phase's
rotation), then `advance_boss_skill!` bumped the index; every later
`action_config` read re-derived through the MERGED `kit` → the cast that
telegraphed skill N reported, resolved, and activated as skill N+1. Two live
convictions, both driven through real `World#tick`s in `grass_fixture`:

1. **The crash (ember_boss, hp 45% → phase 2 `[dash 26f, beam 44f]`, 300 ticks):**

```
NoMethodError: undefined method 'duration' for nil
    src/game/creature.rb:712:in 'Game::Creature#activate_action'
    src/game/creature.rb:685:in 'Game::Creature#advance_attack_state'
    src/game/creature.rb:198:in 'Game::Creature#tick_body'
    src/game/world.rb:600:in 'Game::World#tick_world'
```

   A beam start nils `@dash_plan` (begun cfg's arc != "dash"); the advanced
   index reads the dash cfg at activation → `@dash_plan.duration` on nil.
   A phased boss crashes the session — deterministic on both seats.

2. **The off-by-one (serpent_boss, hp 50% → phase 2 `[spread 30f, arc3 40f]`):**

```
the windup that RAN is not the reported skill's windup — the cast began as one
skill and reports another: [{reported_arc: "arc3", reported_windup: 40,
dash_planned: false, observed_windup: 30, resolved_arc: "arc3"},
{reported_arc: "spread", reported_windup: 30, ..., observed_windup: 40, ...}]
```

   The cast reporting arc3 (40f windup) RAN a 30-frame windup — spread began.
   Key detection insight: pre-fix, EVERY `action_config` read (queued
   :attack_started handler, windup poll, active poll) agreed on the same wrong
   skill — only the cast's physics (windup length actually counted, dash-plan
   presence) tell the truth. `boss_phases_test`'s old handler could not see it
   (T0 a14); the new instrumentation convicts on physics, not on self-report.

## The fix (spec E0 shape, one file)

`src/game/creature.rb`:
- `begin_action` snapshots `@action_cfg = cfg` (the begun skill).
- `action_config` returns the snapshot while an action is live; nil when idle.
- `interrupt_action!` + `initialize` clear it (revive! rides interrupt_action!).
- The boss index still advances at start (rotation grammar unchanged); the
  snapshot keeps THIS cast on skill N. Also freezes hp-phase drift mid-windup
  (a phase transition mid-cast no longer mutates the in-flight skill).
- `:attack_started`/`:special_started` payload shape UNTOUCHED on purpose:
  `EventSerial.describe` serializes every key, `special_started` is a wall
  EVENT line (three banked sim-identity md5s) and every registered event feeds
  the netplay digest — a `cfg:` key would have rebanked every special in every
  stream. Handlers read the begun skill via `attacker.action_config` (correct
  now even though the bus flushes after the advance).
- `@action_cfg` deliberately NOT in `digest_fields`: it is a pure function of
  leaves digested at the begin tick (kind, hp→phase, boss_skill_index) — two
  seats can only disagree on it if they already disagree on digested state.
  Reviewer probed this claim (finding 2 below) — held.

Readers audited (all now see the begun skill): `World#resolve_attacks` /
`apply_action_hit` / `resolve_dash_action` / `resolve_tile_action`,
`activate_action`, `action_tiles`, `apply_special_refund!`,
`renderer.rb:1131` petrify tint + `:1302`/`:1332` dash telegraphs.
`controllers.rb:453/477` read `kit[:attack]` live on purpose (AI ranges for the
NEXT cast — post-advance skill — unchanged semantics pre/post fix).
`stats_panel.rb:100` reads the pack member's kit directly (non-boss, live).
