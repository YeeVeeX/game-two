## 2. Decisions taken as dev of record (ONE line each; peers may reverse with one word)

- **D-T1 (owner-pending, "never nag")** — implemented the bolded rec: **legacy seed ONCE,
  keyed by player id**. `migration.legacy_seed_claimed_by` starts UNCLAIMED; the first seated
  player without a record inherits `legacy_level` and the block records that player's id;
  every later newcomer starts at `progression.json new_character.level` (1). Seat order
  breaks a tie when two newcomers arrive together (seat-order law). Surfaced for both
  peers in the checkpoint; nothing gates on it.
- **`legacy_seed_claimed_by` is `false` while unclaimed, not the spec's `null`.** `null` is
  outside the pinned canonical vocabulary (`test_canonical_bytes_raises_on_non_canonical_leaves`
  line "nil is not in the vocabulary") — extending the canonicalizer is a digest-law
  amendment I did not want to smuggle into a persistence ticket. Validator: `false | player id`.
- **Insurance bound = DATA.** Added `"insurance": { "max_stacks": 3 }` to
  `data/balance/death.json` (foundation L8's N=3, still a candidate; T5 owns the tuning).
  Zero behavior: only the validator reads it. Same for `progression.json
  "new_character": { "level": 1 }` (the spec names the key; it did not exist).
- **Harness default ids are seat CONSTANTS (`bot-1`, `bot-2`), not seed-derived.** The spark
  said "bots and harness scenes derive `bot-<seed>`"; a `--bot <seed>` PROCESS does
  (`App::PlayerFile.bot_id`). A World built without `players:` seats `bot-<seat>` because
  facts are seed-independent by law (v18 decision 16, `test_same_facts_different_seeds…`):
  a seed-keyed host id would make facts projected at seed 11 unloadable at seed 999.
- **`form` is RESTORED at apply** (seat 1 resumes the saved body; a seat construction handed
  that body is released; every other seat claims in roster order as before). The spark said
  "seat pointers stay as today", but a persisted fact the load path ignores cannot satisfy
  the round-trip law `facts(apply(facts)) == facts` (THE ROUND-TRIP LANE) — so `form` is
  honored. Player-visible consequence: you resume in the body you quit in (today you always
  came back as the blocker if it lived). The 2→3 migration sets `form` to exactly the body
  the v2 pointer law resumed (blocker if alive, else the first living kit) — a migrated save
  resumes in the same body it did yesterday. Named for the reviewers.
- **T1 interim rule (council s133 Q5/Q6), written in `Character`/`Party` headers and
  test-pinned:** host character = the shared progression (live); a SEATED guest's
  `level/xp` MIRROR the host's in live reads AND in the clean-quit projection ("in this field
  every seated character IS the party level"); a guest's other keys are frozen at their
  stored values; UNSEATED records round-trip verbatim. Named window: between T1 and T2b a
  fresh third player joining a level-13 host is written at 13 — the alternative (freeze the
  guest's record) would make Junior lose every level the two of them earn together until
  T2b; with two peers the mirror is the right default. T2b retires the rule.
- **Bag persistence hook for Junior's S2 = one line**, proven by the mutation-sweep leaf
  `character.bag` (`w.party.host.bag << item` round-trips). Optional keys `bag [] equipment
  {} attributes {} bank_items []` INSIDE the record; the validator accepts absent = default;
  the projector always WRITES every key; every nested leaf must be Integer / ASCII String /
  Boolean (named refusal with its path, never an EncodeError at quit).
- **`players:` is required on `Net::Session` (no default).** A forgotten id would silently
  seat a stranger; main.rb is the only production caller.
- **`Game::Party` exists now** (T2a's "carve Party" becomes "grow Party" — it will own the
  body/forms in the field). It is a plain object with callables for the host's live facts
  (the Crossing/Homecoming pattern), no World dependency inside `character.rb`.
